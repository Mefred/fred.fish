Application Layer and Common Services

Understand DNS, DHCP, HTTP(S), SSH, file transfer, NTP, SNMP, and Syslog.

1. Core concepts

Application protocols define how clients and servers exchange data. DNS resolves names to records such as A and AAAA; queries commonly use UDP 53, with TCP 53 also used. DHCPv4 assigns addresses and options using UDP 67 (server) and 68 (client), following Discover, Offer, Request, Acknowledge.

2. How it works

Common services: SSH TCP 22; Telnet TCP 23; HTTP TCP 80; HTTPS TCP 443; FTP TCP 21 control plus data channel; TFTP UDP 69; NTP UDP 123; SNMP UDP 161 queries and 162 traps; Syslog commonly UDP 514. SNMPv3 adds authentication and privacy; Telnet is plaintext.

3. Worked example

A browser resolves portal.example through DNS, then connects to the returned server address over HTTPS. DNS and HTTPS are separate exchanges. A service can fail even when IP reachability works if the server process is down or its port is blocked.

IOS XE commands and verification

Syntax and feature availability can vary by device family and software release. Confirm platform support before applying configuration.

show hosts
show ntp status
show logging
show snmp
show ip dhcp binding

Common mistakes and troubleshooting

  • Check physical and interface state before changing higher-layer settings.
  • Verify both ends agree on addressing, VLAN, encapsulation, and protocol parameters.
  • Use operational show commands; configured text alone does not prove a feature is working.
  • Change one variable at a time and verify the result.
