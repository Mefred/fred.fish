Static and Default Routing

Configure connected, static, floating static, and default routes for IPv4 and IPv6, then verify path selection.

CCNA 200-301IP CONNECTIVITY3 QUESTION QUIZ

Learning objectives

  • Explain the purpose and scope of Static and Default Routing.
  • Identify important protocols, roles, fields, and terminology.
  • Apply the concept to a practical network scenario.
  • Use IOS XE commands to verify operational behavior.

1. Core concepts

A connected route is installed for a configured, operational interface subnet. A local route represents the interface's own address. Static routes are manually configured; dynamic routes are learned from protocols. A default route 0.0.0.0/0 or ::/0 is fallback when no more specific route matches.

2. How it works

A static route can specify a next-hop address, exit interface, or both. On Ethernet multi-access networks, specifying a next hop is generally important. Cisco administrative distance compares route sources; lower is preferred. A floating static route uses a higher AD than the primary route to act as backup.

3. Worked example

Configure ip route 0.0.0.0 0.0.0.0 203.0.113.1 for an IPv4 default route. A backup route through 198.51.100.1 can use AD 200 so it is less preferred while the primary exists.

IOS XE commands and verification

Syntax and feature availability can vary by device family and software release. Confirm platform support before applying configuration.

ip route 0.0.0.0 0.0.0.0 203.0.113.1
ip route 0.0.0.0 0.0.0.0 198.51.100.1 200
ipv6 route ::/0 2001:db8:ffff::1
show ip route
show ipv6 route

Common mistakes and troubleshooting

  • Check physical and interface state before changing higher-layer settings.
  • Verify both ends agree on addressing, VLAN, encapsulation, and protocol parameters.
  • Use operational show commands; configured text alone does not prove a feature is working.
  • Change one variable at a time and verify the result.
