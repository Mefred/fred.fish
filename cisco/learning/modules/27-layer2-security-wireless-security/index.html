Layer 2 and Wireless Security

Protect access ports and wireless networks using port security, DHCP snooping, DAI, and modern WLAN security.

Learning objectives

1. Core concepts

Port security limits the source MAC addresses allowed on a switch access port. Static or sticky secure MAC addresses can be used. Violation actions include protect, restrict, and shutdown, with exact behavior depending on mode. Port security is commonly used on edge/access ports, not indiscriminately on trunks.

2. How it works

DHCP snooping distinguishes trusted and untrusted switch ports and blocks unauthorized DHCP server messages on untrusted ports. It builds a binding table. Dynamic ARP Inspection validates ARP packets against trusted bindings to reduce ARP spoofing. IP Source Guard can use binding information to restrict source IP/MAC traffic. WLAN security should use WPA2-AES or WPA3 and enterprise 802.1X where appropriate.

3. Worked example

Trust uplinks toward legitimate DHCP servers and leave user-facing ports untrusted. Enable DHCP snooping for the VLANs, then DAI where supported. On wireless, avoid WEP and legacy TKIP. Use WPA3 or WPA2-AES, strong credentials, and 802.1X/RADIUS for enterprise access.

IOS XE commands and verification

Syntax and feature availability can vary by device family and software release. Confirm platform support before applying configuration.

interface gi1/0/10
 switchport mode access
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
ip dhcp snooping
ip dhcp snooping vlan 10,20
ip arp inspection vlan 10,20
show port-security interface gi1/0/10
show ip dhcp snooping binding

Common mistakes and troubleshooting

  • Check physical and interface state before changing higher-layer settings.
  • Verify both ends agree on addressing, VLAN, encapsulation, and protocol parameters.
  • Use operational show commands; configured text alone does not prove a feature is working.
  • Change one variable at a time and verify the result.
