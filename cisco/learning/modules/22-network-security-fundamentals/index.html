1. Core concepts

Threats include reconnaissance, password attacks, spoofing, denial of service, malware, rogue devices, and misconfiguration. Defense in depth combines physical security, segmentation, access control, secure management, monitoring, patching, and backups. Least privilege limits access to what is required.

2. How it works

Use SSH instead of Telnet. Standard IPv4 ACLs primarily match source addresses; extended ACLs can match source/destination, protocol, and ports. ACLs are processed top-down and stop at first match. An implicit deny exists at the end. Port security limits MAC learning; DHCP snooping blocks rogue DHCP messages; DAI validates ARP.

3. Worked example

An extended ACL can permit HTTPS from 192.168.10.0/24 to server 192.0.2.20 and deny other traffic to that server. A management ACL restricts SSH to a trusted admin subnet. Account for implicit deny and verify intended traffic before applying.

show ip dhcp snooping

Common mistakes and troubleshooting

  • Check physical and interface state before changing higher-layer settings.
  • Verify both ends agree on addressing, VLAN, encapsulation, and protocol parameters.
  • Use operational show commands; configured text alone does not prove a feature is working.
  • Change one variable at a time and verify the result.
