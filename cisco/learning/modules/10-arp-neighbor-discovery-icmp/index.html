ARP, Neighbor Discovery, and ICMP

Resolve local next-hop addresses and use ICMP tools to diagnose network reachability.

CCNA 200-301NETWORK FUNDAMENTALS / IP CONNECTIVITY3 QUESTION QUIZ

Learning objectives

  • Explain the purpose and scope of ARP, Neighbor Discovery, and ICMP.
  • Identify important protocols, roles, fields, and terminology.
  • Apply the concept to a practical network scenario.
  • Use IOS XE commands to verify operational behavior.

1. Core concepts

ARP maps an IPv4 address to a MAC address on a local broadcast domain. A host broadcasts an ARP request and caches the reply. For a remote destination, it resolves its default gateway's MAC, not the remote server. Routers do not forward ARP broadcasts.

2. How it works

IPv6 uses Neighbor Discovery over ICMPv6, including Neighbor Solicitation and Advertisement for address resolution and Router Solicitation/Advertisement for router discovery. IPv6 uses multicast rather than broadcast. ICMP provides Echo, Destination Unreachable, and Time Exceeded messages.

3. Worked example

Host 192.168.1.10/24 sending to 192.168.1.20 ARPs for .20. Sending to 8.8.8.8 causes it to ARP for its default gateway, e.g. 192.168.1.1. Ping uses ICMP Echo; traceroute relies on hop-limit expiry and ICMP Time Exceeded.

IOS XE commands and verification

Syntax and feature availability can vary by device family and software release. Confirm platform support before applying configuration.

show ip arp
show ipv6 neighbors
ping 192.168.1.1
traceroute 8.8.8.8

Common mistakes and troubleshooting

  • Check physical and interface state before changing higher-layer settings.
  • Verify both ends agree on addressing, VLAN, encapsulation, and protocol parameters.
  • Use operational show commands; configured text alone does not prove a feature is working.
  • Change one variable at a time and verify the result.
